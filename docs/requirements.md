# Требования к системе

## 1. Общая информация

Проект представляет собой веб-приложение для учёта оборудования и аудиторий колледжа

Система должна позволять:
- вести учёт оборудования;
- распределять оборудование по аудиториям;
- оформлять выдачу и возврат оборудования;
- хранить историю перемещений;
- управлять пользователями и ролями;
- просматривать статистику;
- выполнять поиск, фильтрацию, сортировку и пагинацию данных.

## 2. Роли пользователей

В системе предусмотрено 3 роли:

- преподаватель;
- лаборант;
- администратор.

## 3. Возможности преподавателя

Преподаватель может:

- зарегистрироваться и войти в систему;
- просматривать доступное оборудование;
- искать оборудование;
- фильтровать оборудование по категории, аудитории и статусу;
- просматривать информацию об оборудовании;
- создавать запрос на получение оборудования;
- просматривать свои запросы;
- просматривать оборудование, выданное ему;
- просматривать историю своих выдач и возвратов;
- редактировать данные своего профиля;
- изменять пароль.

Преподаватель не может:

- создавать и удалять оборудование;
- редактировать данные оборудования;
- управлять аудиториями;
- управлять пользователями;
- изменять роли пользователей.

## 4. Возможности лаборанта

Лаборант может:

- входить в систему;
- просматривать список оборудования;
- создавать оборудование;
- редактировать оборудование;
- удалять оборудование с подтверждением;
- управлять категориями оборудования;
- просматривать запросы преподавателей;
- подтверждать или отклонять запросы;
- оформлять выдачу оборудования;
- оформлять возврат оборудования;
- перемещать оборудование между аудиториями;
- просматривать историю перемещений оборудования;
- искать, сортировать и фильтровать оборудование;
- просматривать статистику по оборудованию;
- редактировать данные своего профиля;
- изменять пароль.

## 5. Возможности администратора

Администратор имеет полный доступ к системе

Администратор может:

- просматривать список пользователей;
- создавать пользователей;
- редактировать пользователей;
- блокировать и разблокировать пользователей;
- изменять роли пользователей;
- управлять аудиториями;
- управлять оборудованием;
- управлять категориями оборудования;
- просматривать все запросы;
- просматривать историю выдачи и возврата;
- просматривать журнал действий пользователей;
- просматривать общую статистику системы;
- экспортировать отчёты;
- редактировать данные своего профиля;
- изменять пароль.

## 6. Основные сущности системы

В проекте будут использоваться следующие сущности:

1. Пользователи
2. Роли
3. Оборудование
4. Категории оборудования
5. Аудитории
6. Запросы на получение оборудования
7. Операции выдачи и возврата
8. Журнал аудита

## 7. Дополнительный функционал

В качестве дополнительного функционала будут реализованы:

- журнал аудита действий пользователей;
- экспорт отчётов в PDF или XLSX.

## 8. Общие требования

Система должна:

- поддерживать регистрацию и аутентификацию;
- использовать JWT access и refresh токены;
- проверять права доступа на сервере;
- выполнять валидацию данных на клиенте и сервере;
- поддерживать загрузку файлов;
- иметь адаптивный интерфейс;
- корректно работать на экранах от 360 px до 1920 px;
- использовать PostgreSQL;
- запускаться через Docker Compose;
- иметь документацию REST API;
- иметь автоматические тесты;
- иметь CI для проверки кода.
