# User Stories

## Преподаватель

### US-01. Регистрация

Как преподаватель, я хочу зарегистрироваться в системе, чтобы получить доступ к учёту оборудования

**Критерии приёмки:**
- пользователь вводит имя, email и пароль;
- email должен быть уникальным;
- пароль проходит проверку требований безопасности;
- после успешной регистрации пользователь может войти в систему;
- при ошибке отображается понятное сообщение.

### US-02. Авторизация

Как преподаватель, я хочу войти в систему по email и паролю, чтобы получить доступ к своему личному кабинету

**Критерии приёмки:**
- пользователь может ввести email и пароль;
- при корректных данных система выполняет вход;
- при неправильных данных выводится сообщение об ошибке;
- после входа пользователь получает доступ только к разрешённым своей ролью функциям.

### US-03. Просмотр оборудования

Как преподаватель, я хочу просматривать список оборудования, чтобы узнать, какое оборудование есть в колледже

**Критерии приёмки:**
- отображается список оборудования;
- для каждой позиции отображаются название, категория, аудитория и статус;
- список поддерживает пагинацию;
- данные загружаются с сервера.

### US-04. Поиск и фильтрация оборудования

Как преподаватель, я хочу искать и фильтровать оборудование, чтобы быстрее находить нужную технику

**Критерии приёмки:**
- доступен поиск по названию;
- доступна фильтрация по категории;
- доступна фильтрация по аудитории;
- доступна фильтрация по статусу;
- поиск и фильтрация выполняются на сервере.

### US-05. Создание запроса на оборудование

Как преподаватель, я хочу создать запрос на получение оборудования, чтобы использовать его для проведения занятий

**Критерии приёмки:**
- пользователь может выбрать доступное оборудование;
- пользователь указывает необходимые данные запроса;
- система не позволяет создать запрос на недоступное оборудование;
- после создания запрос получает статус «Ожидает рассмотрения»;
- преподаватель видит созданный запрос в личном кабинете.

### US-06. Просмотр своих запросов

Как преподаватель, я хочу просматривать свои запросы, чтобы отслеживать их состояние

**Критерии приёмки:**
- преподаватель видит только собственные запросы;
- отображается текущий статус запроса;
- отображаются дата создания и выбранное оборудование;
- чужие запросы недоступны даже при изменении ID в URL.

### US-07. Просмотр истории выдачи

Как преподаватель, я хочу видеть историю полученного и возвращённого оборудования, чтобы отслеживать свои прошлые операции

**Критерии приёмки:**
- отображаются только операции текущего пользователя;
- для каждой операции указаны оборудование, дата выдачи и дата возврата;
- информация недоступна другим преподавателям.

## Лаборант

### US-08. Добавление оборудования

Как лаборант, я хочу добавлять новое оборудование, чтобы поддерживать актуальный список техники колледжа

**Критерии приёмки:**
- можно указать название оборудования;
- можно выбрать категорию и аудиторию;
- можно указать инвентарный номер;
- обязательные поля проходят валидацию;
- после сохранения оборудование появляется в общем списке.

### US-09. Редактирование и удаление оборудования

Как лаборант, я хочу редактировать и удалять оборудование, чтобы поддерживать данные в актуальном состоянии

**Критерии приёмки:**
- данные оборудования можно изменить;
- перед удалением система запрашивает подтверждение;
- изменения сохраняются в базе данных;
- пользователь без соответствующих прав не может выполнить эти действия.

### US-10. Обработка запросов

Как лаборант, я хочу подтверждать или отклонять запросы преподавателей, чтобы контролировать выдачу оборудования

**Критерии приёмки:**
- лаборант видит список ожидающих запросов;
- запрос можно подтвердить;
- запрос можно отклонить;
- после обработки статус запроса изменяется;
- преподаватель видит обновлённый статус.

### US-11. Выдача и возврат оборудования

Как лаборант, я хочу оформлять выдачу и возврат оборудования, чтобы система отражала его фактическое состояние

**Критерии приёмки:**
- при выдаче создаётся запись об операции;
- статус оборудования изменяется на «Выдано»;
- при возврате фиксируется дата возврата;
- статус оборудования снова становится доступным;
- система хранит историю операций.

### US-12. Перемещение оборудования

Как лаборант, я хочу перемещать оборудование между аудиториями, чтобы в системе всегда отображалось его актуальное местоположение

**Критерии приёмки:**
- можно выбрать новую аудиторию;
- новое местоположение сохраняется;
- операция фиксируется в истории;
- недопустимая аудитория не может быть назначена.

## Администратор

### US-13. Управление пользователями

Как администратор, я хочу управлять пользователями, чтобы контролировать доступ к системе

**Критерии приёмки:**
- администратор видит список пользователей;
- можно редактировать данные пользователя;
- можно блокировать и разблокировать пользователя;
- заблокированный пользователь не может войти в систему;
- обычные пользователи не имеют доступа к управлению пользователями.

### US-14. Управление ролями

Как администратор, я хочу изменять роли пользователей, чтобы назначать им необходимые права доступа

**Критерии приёмки:**
- администратор может выбрать роль пользователя;
- изменение сохраняется в базе данных;
- новые права применяются после изменения роли;
- обычный пользователь не может изменить собственную роль.

### US-15. Просмотр дашборда

Как администратор, я хочу просматривать сводную статистику, чтобы быстро оценивать состояние оборудования колледжа

**Критерии приёмки:**
- отображается общее количество оборудования;
- отображается количество доступного и выданного оборудования;
- отображается минимум один график;
- данные дашборда загружаются с сервера.

### US-16. Журнал аудита и экспорт отчётов

Как администратор, я хочу просматривать журнал действий и экспортировать данные, чтобы контролировать изменения в системе и формировать отчётность

**Критерии приёмки:**
- система фиксирует значимые действия пользователей;
- для записи журнала отображаются пользователь, действие и дата;
- журнал доступен только администратору;
- администратор может сформировать отчёт;
- отчёт можно экспортировать в PDF или XLSX.
